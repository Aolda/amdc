# 보고서 템플릿 v0.1: 대표 사례별 기대 출력

빈 결과·시간 초과·관측 불일치·결과 잘림의 합성 사례로 상세 7구획과 Discord 기대 문구를 비교한다. 정제 근거가 필요한 목표 출력과 현재 입력으로 가능한 표현을 구분하며, 제품 실행 결과로 취급하지 않는다.

작성일: 2026-10-02 · 상태: 합의된 v0.1 구조의 합성 기대 출력

구조 합의의 범위와 테스트에 따른 개선 원칙은 [템플릿 v0.1](report-template-v0.1.md#v01-구조-합의와-개선-원칙)을 따른다. 이 자료는 후속 테스트의 비교 기준이며 사례별 의미 검토와 제품 검증 완료를 뜻하지 않는다.

## 공통 전제와 표기

모든 시각·연결 번호·대상은 합성이다. 실제 AMDB 기록, 실행된 도구 출력, 현재 스키마에 맞는 JSON fixture가 아니다. 아래 입력표의 잠금 관계는 후속 정규화 계약이 제공해야 할 **의미 수준의 허용 사실 후보**를 사람이 적은 것이다. 원시 SQL 행을 전달한 것이 아니며 이 문서가 해당 값을 모델·보고서에 보내도록 승인하지 않는다.

네 목표 보고서는 전용 정규화기가 사실·대상·시각·참조·크기를 검증했다는 조건부 기대 출력이다.

현재 MVP에 그 사실 입력이 없으므로 그대로 생성할 수 없다. 각 사례 끝의 “현재 입력만 있을 때”는 같은 자료에서 현재 코드가 보존하는 메타데이터만으로 쓸 수 있는 표현이다. 이 표현도 현재 포매터가 실제 생성한 문자열을 캡처한 것은 아니다.

표시용 `call-N`은 각 사례의 진단 ID에 속한 정확한 `<diagnosis_id>:call-N`의 약칭이다. 사례 간 ID를 연결하지 않는다. 숫자를 `tc_`/`ev_`로 바꾸지 않는다. 제품 표시에서는 저장된 전체 ID와의 대응을 보존해야 한다.

- A 진단 ID: `diag-00000000-0000-4000-8000-00000000000a`
- B 진단 ID: `diag-00000000-0000-4000-8000-00000000000b`
- C 진단 ID: `diag-00000000-0000-4000-8000-00000000000c`
- D 진단 ID: `diag-00000000-0000-4000-8000-00000000000d`

공통 사례 전제: 합성 대상 별칭은 `sample-db`, 도구는 `mysql_get_lock_waits`, 검토 목적은 요청된 지연과 잠금 대기의 관련성 확인이다. 대상 별칭·검토 목적도 현재 Report 투영에는 없다. 시간은 모두 2026-09-18 UTC의 호출 기록 시각이며 측정 구간·연속 관측을 뜻하지 않는다.

실제 요청 지연, 요청-연결 대응, 필터·전체 검사 범위, 트랜잭션 동일성·상태는 제공하지 않는다. 아래 “미제공” 판단은 이 사례 전제에 근거한다.

## 사례 A: 성공→성공→빈 결과

합성 입력: `completion_reason=investigation_complete`. 종료 이유만으로 필요한 검사를 모두 마쳤다고 판단하지 않는다.

| 호출 | 기록 시각 | 실행 기록 | 조건부 정제 관측 |
|---|---|---|---|
| call-1 | 10:00:00 | success, 반환 1행, 잘림 false | 연결 386이 382의 잠금 해제를 기다리는 관계 |
| call-2 | 10:01:00 | success, 반환 1행, 잘림 false | 연결 386이 382의 잠금 해제를 기다리는 관계 |
| call-3 | 10:02:00 | success, 반환 0행, 잘림 false | 이번 조회의 반환 행 없음 |

### 1. 진단 요약

앞선 두 조회에 연결 386이 382의 잠금 해제를 기다리는 관계가 기록됐습니다. [call-1, call-2]

마지막 조회의 반환 행은 0건입니다. [call-3]

잠금 대기가 지연에 영향을 주었을 가능성은 있으나 원인은 미확정이며, 빈 결과만으로 증상 해소를 확인할 수 없습니다.

---

### 2. 조사 대상·범위

사례 전제의 sample-db 지연 관련 자료로, 10:00·10:01·10:02 UTC의 잠금 대기 조회 3건을 검토했습니다. [call-1, call-2, call-3]

각 호출의 반환 결과만 다룹니다. 측정 구간·필터·실제 지연값과 필수 검사 충족 여부는 미제공입니다.

종료 이유는 진단 에이전트의 조사 종료입니다.

---

### 3. 확인된 사실

| 종류 | 사실 | 호출 근거 |
|---|---|---|
| 원천 관측 | 10:00 기록에 연결 386→382의 잠금 대기 관계가 있습니다. | call-1 |
| 원천 관측 | 10:01 기록에도 같은 연결 번호의 대기 관계가 있습니다. | call-2 |
| 실행 기록 | 10:02 조회는 성공했고 반환 행은 0건이며 잘림 표식은 false입니다. | call-3 |

---

### 4. 원인 가설과 근거

가능성: 관측된 잠금 대기가 요청된 지연에 영향을 주었을 수 있습니다. [call-1, call-2]

요청과 연결 번호의 대응이 없어 인과관계는 확인되지 않았습니다. 마지막 빈 결과는 앞선 관측을 지우거나 복구를 증명하지 않습니다. [call-3]

---

### 5. 조사 한계·조회 실패

제공된 세 기록은 모두 성공이며 잘림 표식은 false입니다. [call-1, call-2, call-3]

다만 연속 관측이 아니므로 대기가 2분 지속됐다고 말할 수 없습니다. 같은 연결 번호가 같은 트랜잭션임을 뜻하지 않습니다. 지연 측정값과 전체 검사 범위가 없고, 마지막 0행으로 전체 정상·복구를 판단할 수 없습니다. [call-3]

---

### 6. 후속 확인 사항

| 확인 항목 | 목적 |
|---|---|
| 지연이 발생한 시각과 요청-연결 대응 | 앞선 대기 관계와 증상의 관련성을 확인합니다. |
| 해당 시점의 트랜잭션 정보 | 연결 382가 잠금을 유지한 이유를 좁힙니다. |
| 현재 증상과 후속 관측의 확인 가능 여부 | 마지막 빈 결과 이후 증상이 남아 있는지 검토합니다. |

담당자의 확인 항목이며 자동 실행 지시가 아닙니다.

---

### 7. 호출별 상세 근거

| 호출 ID 약칭 | 도구 | 기록 시각 | 허용된 결과 요약 |
|---|---|---|---|
| call-1 | mysql_get_lock_waits | 10:00:00 | 성공, 1행, 386→382 대기 관계, 잘림 false |
| call-2 | mysql_get_lock_waits | 10:01:00 | 성공, 1행, 386→382 대기 관계, 잘림 false |

## 사례 C: 관측 불일치와 근거 부족

합성 입력: `completion_reason=insufficient_evidence`. 동일한 기록 시각의 반환 내용이 다릅니다. 실제 측정 시점·필터가 같다는 자료는 없으므로 논리적 모순이나 상태 변화로 확정하지 않습니다. call-2의 진단 코멘트에는 “잠금 대기가 해소됐다”는 **미검증 해석**이 있다고 가정합니다.

| 호출 | 기록 시각 | 실행 기록 | 조건부 정제 관측 |
|---|---|---|---|
| call-1 | 10:00:00 | success, 반환 1행, 잘림 false | 연결 386이 382의 잠금 해제를 기다리는 관계 |
| call-2 | 10:00:00 | success, 반환 0행, 잘림 false | 이번 조회의 반환 행 없음 |

### 1. 진단 요약

한 조회에는 386→382의 대기 관계가 있고 다른 조회의 반환 행은 0건입니다. [call-1, call-2]

기록 시각은 같습니다. [call-1, call-2]

조회 조건과 측정 구간을 대조할 수 없어 결과 차이를 설명하지 못했습니다. 원인 가설과 정상·복구 판단을 보류합니다.

---

### 2. 조사 대상·범위

사례 전제의 sample-db에 대한 두 기록을 비교했습니다. 두 기록의 시각 표기는 10:00 UTC입니다. [call-1, call-2]

### 자동 구조 점검 재현

PowerShell 7에서 `docs/design`을 현재 경로로 두고 아래를 실행한다. 이는 문서 구조와 표식 검사다. `Length`는 현재 MVP 포매터와 같은 UTF-16 코드 단위로 세며 문구의 의미는 판정하지 않는다.

```powershell
$ErrorActionPreference = 'Stop'
$text = Get-Content -LiteralPath './report-template-v0.1-examples.md' -Raw
$cases = [regex]::Matches($text, '(?ms)^## 사례 ([A-D]):.*?(?=^## 사례 |^## 검증 기록)')
if ($cases.Count -ne 4) { throw 'Expected four cases' }
$titles = @('진단 요약','조사 대상·범위','확인된 사실','원인 가설과 근거','조사 한계·조회 실패','후속 확인 사항','호출별 상세 근거')
$markers = @{ A=@('반환 0행','증상 해소','전체 검사'); B=@('시간 초과','결과 미확보','전체 검사'); C=@('조회 조건','측정 구간','판단을 보류','미검증'); D=@('잘려','전체 규모','영향 순위','전체 검사') }
$totalFacts = 0
foreach ($case in $cases) {
    $key = $case.Groups[1].Value
    $body = $case.Value
    for ($n=0; $n -lt 7; $n++) {
        $heading = '### {0}. {1}' -f ($n+1),$titles[$n]
        if ([regex]::Matches($body, '(?m)^'+[regex]::Escape($heading)+'\r?$').Count -ne 1) { throw "$key heading" }
    }
    $inputPart = ($body -split '(?m)^### 1\.')[0]
    $ids = @([regex]::Matches($inputPart, '(?m)^\| (call-\d+) \|') | ForEach-Object { $_.Groups[1].Value })
    foreach ($ref in [regex]::Matches($body, 'call-\d+')) {
        if ($ref.Value -notin $ids) { throw "$key unknown reference $($ref.Value)" }
    }
    $facts = [regex]::Match($body, '(?ms)^### 3\..*?(?=^### 4\.)').Value
    $rows = @($facts -split '\r?\n' | Where-Object { $_ -match '^\| (원천 관측|실행 기록)' })
    if ($rows.Count -eq 0) { throw "$key missing facts" }
    foreach ($row in $rows) {
        if ($row -notmatch '\| call-\d+(, call-\d+)* \|$') { throw "$key uncited fact" }
    }
    $totalFacts += $rows.Count
    $discord = [regex]::Match($body, '(?ms)^### Discord 기대 출력\r?\n(.*?)(?=^### 현재 입력만)').Groups[1].Value
    $discord = (($discord -split '\r?\n' | Where-Object { $_ -match '^>( |$)' }) -replace '^> ?', '') -join "`n"
    if ($discord.Length -eq 0 -or $discord.Length -gt 1900) { throw "$key Discord length" }
    foreach ($marker in $markers[$key]) {
        if (-not $discord.Contains($marker)) { throw "$key missing marker $marker" }
    }
    '{0}: facts={1}, calls={2}, Discord={3}' -f $key,$rows.Count,$ids.Count,$discord.Length
}
foreach ($file in @('report-template-v0.1.md','report-template-v0.1-examples.md','report-template-discussion-2026-09-22.md')) {
    $summary = ((Get-Content -LiteralPath $file -Raw) -split '\r?\n\r?\n')[1]
    if ($summary.Length -gt 200) { throw "$file summary exceeds 200" }
    '{0}: summary={1}' -f $file,$summary.Length
}
'fact rows with references: {0}/{0}' -f $totalFacts
```

링크의 파일·절 존재 확인과 변경 범위의 `git diff --check`는 별도로 수행한다. 위 스크립트는 같은 ID가 내용상 올바른 근거인지, 자유형 문장이 과장됐는지 또는 실제 포매터가 이 출력과 일치하는지 검증하지 않는다.

미검증: 사례별 사람의 의미 검토·후속 계약 승인, 정제 근거 생산자 구현, 현재 모델/포매터와의 실행 비교, 다수 한계·최대 크기 입력의 보존, 저장·실전송·동시성·메모리·복구 검증. 제품 통과율이나 프로젝트 완료로 보고하지 않는다.

같은 날 가독성 편집에서 구획 구분선, 의미별 문단, Discord 문단 여백과 항목 강조를 반영했다. 위 길이는 편집 후 다시 측정한 값이다. 사례의 사실·가설·한계와 7구획 순서는 유지하며, 제품 포매터 구현은 변경하지 않는다.
